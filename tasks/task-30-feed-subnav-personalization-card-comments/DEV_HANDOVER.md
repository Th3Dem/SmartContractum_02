## 1. Реализованная серверная логика (py_bot)

### 1.1. База данных SQLite (`server.py`)
- В функции `init_db` добавлены таблицы:
  * `article_likes`: `id INTEGER PRIMARY KEY AUTOINCREMENT`, `article_id TEXT NOT NULL`, `user_id TEXT NOT NULL`, `created_at TEXT NOT NULL`, `UNIQUE(article_id, user_id)`. Созданы индексы `idx_likes_article_user` по `(article_id, user_id)` и `idx_likes_article_id` по `article_id`.
  * `article_comments`: `id TEXT PRIMARY KEY`, `article_id TEXT NOT NULL`, `user_id TEXT NOT NULL`, `author_name TEXT NOT NULL`, `author_avatar TEXT`, `content TEXT NOT NULL`, `status TEXT NOT NULL DEFAULT 'published'`, `created_at TEXT NOT NULL`. Создан индекс `idx_comments_article_id` по `article_id`.
  * `user_feed_settings`: `user_id TEXT PRIMARY KEY`, `material_types TEXT NOT NULL`, `complexity_levels TEXT NOT NULL`, `updated_at TEXT NOT NULL`.
- Реализована функция `seed_article_comments(conn)`:
  * Идемпотентный сидинг 3 демонстрационных комментариев для публикации `art-01`:
    1. Автор «Тестовый читатель 1»: «Было бы полезно увидеть пример обработки ошибки во время исполнения контракта.»
    2. Автор «Тестовый читатель 2»: «Планируется ли отдельный материал о проверке данных оракула?»
    3. Автор «Тестовый читатель 3»: «Спасибо за разбор. Особенно интересен раздел о тестировании.»
  * Засеивание выполняется с `INSERT OR IGNORE` по первичным ключам, гарантируя отсутствие дубликатов при повторных запусках.

### 1.2. Поддержка типов материалов (`materialType` / `type`)
- Заданы допустимые типы материалов: `VALID_MATERIAL_TYPES = ("article", "post", "news", "question")`.
- В существующих статьях и по умолчанию используется тип `article` («Статья»).
- В `validate_submission_payload` добавлена валидация опционального поля `materialType` (или `type`): при передаче проверяется соответствие допустимым типам и сохраняется в `publication_settings`.

### 1.3. Эндпоинты настроек ленты пользователя (`/api/user/feed-settings`)
- `GET /api/user/feed-settings`:
  * Для авторизованного пользователя возвращает сохраненные настройки `materialTypes` и `complexityLevels`.
  * Для гостей и пользователей без сохраненных настроек возвращает дефолтные значения: `materialTypes: ["article", "post", "news", "question"]` и `complexityLevels: ["all"]`.
- `POST /api/user/feed-settings`:
  * Требует авторизации (для гостей — статус `401` и `requireAuth: True`).
  * Валидирует `materialTypes`: список не может быть пустым. При попытке отключить все типы или передать пустой массив возвращает статус `400` с текстом ошибки: «Выберите хотя бы один тип материала».
  * Сохраняет актуальные настройки в таблицу `user_feed_settings`.

### 1.4. Эндпоинт отметок «Нравится» (`/api/articles/<id>/like` и `/api/likes/toggle`)
- Поддерживает вызовы `POST /api/articles/<id>/like` и `POST /api/likes/toggle` с телом `{"articleId": "..."}`.
- Требует авторизации (для неавторизованных — статус `401` и `requireAuth: True`).
- Реализует переключение (тоггл): повторный запрос снимает отметку, соблюдая инвариант «1 пользователь = 1 лайк».
- Возвращает `{ success: True, hasLiked: bool, likesCount: int, articleId: str }`.

### 1.5. Эндпоинты комментариев (`/api/articles/<id>/comments`)
- `GET /api/articles/<id>/comments`:
  * Доступен гостям и авторизованным пользователям.
  * Возвращает список опубликованных комментариев со структурой `[{ id, articleId, userId, authorName, authorAvatar, content, createdAt }]` и общее количество `total`.
- `POST /api/articles/<id>/comments`:
  * Требует авторизации (для гостей — статус `401` и `requireAuth: True`).
  * Валидирует текст: запрещены пустые строки и строки только из пробелов (`400`).
  * Проверяет лимит длины: не более 5000 символов (`400`).
  * Безопасно экранирует HTML (`html.escape`), защищая от XSS-инъекций.
  * Сохраняет комментарий в `article_comments` со статусом `published` и возвращает созданный объект комментария вместе с обновленным `commentsCount` (`201 Created`).

### 1.6. Обновление API выдачи статей (`GET /api/articles` и `GET /api/articles/<id>`)
- В объектах публикаций возвращаются поля:
  * `likesCount`: суммарное количество лайков статьи.
  * `hasLiked`: флаг (True/False), поставил ли текущий пользователь лайк.
  * `commentsCount`: суммарное количество опубликованных комментариев к статье.
  * `materialType` и `type`: тип материала публикации.
- Фильтрация в `GET /api/articles`:
  * Параметры `types` (через запятую) и `type`: выборка публикаций по типам (`article`, `post`, `news`, `question`).
  * Параметры `complexities` (через запятую) и `complexity`: выборка публикаций по уровням сложности, включая вариант `unspecified` для публикаций без указанной сложности.
  * Режим `tab=my`: выборка материалов с учетом сохраненных предпочтений пользователя (типы + сложность) и наличия хотя бы одной подписки (автор, тема или тег) с дедупликацией материалов.
  * Пустые состояния: если у пользователя нет подписок — отдается `noSubscriptions: True`; если подписки есть, но нет подходящих публикаций под настройки — отдается `noSubscriptions: False` и `total: 0`.

## 3. Реализованный фронтенд (dev_bot)

### 3.1. Вторая панель меню ленты (`frontend/public/feed.html`, `feed.css`, `feed.js`)
- Постоянно закрепленная (sticky) панель `#feedSubnavBar` непосредственно под основной шапкой сайта.
- Расположение элементов слева направо в контейнере 1360px:
  1. «Написать» (`#feed-btn-write`) — левый край, акцентное действие, переход в редактор.
  2. «Настройка ленты» (`#btn-feed-settings`) — открывает выдвижную панель персонализации.
  3. «Фильтры» (`#btn-feed-filters`) — единственная кнопка фильтрации (дублирование внутри панели исключено).
  4. «Моя лента» (`#btn-my-feed`) — переключение персонализированного режима с индикатором активного состояния.
  5. Меню «Сохраненные» (`#btn-saved-menu`) — быстрый доступ к сохраненным материалам.
  6. Группа поиска (`.feed-search-wrap`) справа: поле `#feedSearchInput`, кнопка лупы `#feedSearchBtn`, кнопка очистки `#feedSearchClearBtn`. Плавное раскрытие с 240px до 380px при фокусе с сохранением раскрытого состояния при клике на лупу.

### 3.2. Выдвижная панель «Настройка ленты» (`#feedSettingsDrawer`)
- Выдвигается непосредственно под второй панелью над содержимым ленты со сдвигом контента и ограничением высоты со скроллом.
- Взаимное исключение с панелью быстрых фильтров (открыта только одна из двух панелей).
- Секции:
  * «Типы материалов»: 4 независимых чекбокса («Статьи», «Посты», «Новости», «Вопросы»). Валидация запрета отключения всех с выводом подсказки «Выберите хотя бы один тип материала».
  * «Уровень сложности»: мультивыбор («Любой уровень», «Простой», «Средний», «Сложный», «Не указан»).
  * «Подписки»: управление подписками на авторов, категории (темы) и хэштеги с чипами и поиском.
- Кнопки: «Сохранить настройки» (`#btn-save-feed-settings`) и «Отмена» (`#btn-cancel-feed-settings`), закрытие по клику вне панели или повторному нажатию кнопки в панели навигации.
- Сохранение в аккаунт пользователя через `POST /api/user/feed-settings` и синхронизация с контекстными подписками.

### 3.3. Обновленная карточка публикации (`frontend/public/js/card.js`)
- Полное удаление бейджа «Демонстрационный материал» из карточек ленты и предпросмотра.
- Новая двухстрочная структура нижней части карточки:
  * Служебная строка: дата публикации (перенесена из шапки автора), время чтения, бейдж уровня сложности (если указан).
  * Строка действий: интерактивная кнопка лайка со счетчиком, кнопка комментариев с реальным счетчиком, кнопка закладки, ссылка «Читать далее».
- Сохранение авторской обложки 39:22 на 100% ширины контента без наложений и 0px резервируемого места при отсутствии/ошибке загрузки.

### 3.4. Комментарии и переходы к статьям (`frontend/public/article.html`, `article.js`, `article.css`)
- Клик по заголовку карточки и кнопке «Читать далее» переходит на `article.html?id=...`.
- Клик по кнопке комментариев в карточке ведет на `article.html?id=...#comments` с плавным скроллом и учетом высоты закрепленных шапок.
- Раздел комментариев на странице статьи:
  * Список опубликованных комментариев (автор, аватар, дата, текст).
  * Форма добавления комментария (валидация, защита от двойного клика, лимит 5000 символов с живым счетчиком, безопасное экранирование).
  * Кнопка лайка в статье (`#articleLikeBtn`) с живой синхронизацией состояния и счетчика.

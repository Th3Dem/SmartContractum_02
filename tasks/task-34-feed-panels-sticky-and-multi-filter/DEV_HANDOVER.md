## 1. Архитектура и реализованная функциональность

### 1.1. Закрепление панелей ленты под шапкой (`position: fixed`)
1. **Позиционирование немодального слоя**:
   - Панели «Настройка ленты» (`#feedSettingsPanel`) и «Фильтры» (`#feedFiltersPanel`) переведены из потока документа в закрепленный немодальный слой (`position: fixed; left: 0; right: 0;`).
   - Панель открывается непосредственно под нижней границей второго уровня шапки (`.feed-subnav-bar`) при любой позиции прокрутки ленты через динамическую CSS-переменную `--feed-header-total-height`.
   - В функции `updateFeedPanelsPosition()` в `feed.js` координата `top` рассчитывается в реальном времени по `subnav.getBoundingClientRect().bottom` с привязкой к событиям `scroll`, `resize`, `visualViewport` и переключению панелей.
   - Открытие панели не прокручивает страницу наверх; при прокрутке ленты панель не сдвигается и не уезжает под шапку.
   - Отсутствует блокировка скролла страницы и модальное затемнение (overlay).
   - Одновременно открыта только одна панель, переключение между настройками и фильтрами происходит в том же закрепленном пространстве.
   - Ширина внутреннего контейнера строго согласована с сеткой сайта (`max-width: 1360px`), фон непрозрачен (`var(--feed-surface)`), с аккуратной тенью и нижней границей (`1px solid var(--feed-border)`).

### 1.2. Высота панели и внутренняя прокрутка
1. **Трехуровневая flex-структура**:
   - Заголовок панели (`.feed-slide-panel-header`, `flex: 0 0 auto`).
   - Прокручиваемое содержимое (`.feed-slide-panel-body`, `flex: 1 1 auto; overflow-y: auto; overscroll-behavior: contain`).
   - Закрепленная нижняя область действий (`.feed-slide-panel-footer`, `flex: 0 0 auto; position: sticky; bottom: 0; z-index: 20`).
2. **Изоляция прокрутки**:
   - Максимальная высота ограничена доступной видимой областью под шапкой: `max-height: calc(100vh - var(--feed-header-total-height))`.
   - Короткая панель занимает естественную высоту контента; длинная аккуратно прокручивается внутри тела.
   - Свойство `overscroll-behavior: contain` предотвращает паразитную передачу прокрутки публикациям ленты при достижении границ панели.
   - Кнопки («Сохранить настройки», «Применить фильтры», «Отмена», «Сбросить») всегда на виду и не перекрываются содержимым.

### 1.3. Множественный выбор форматов публикации
1. **Компонент множественного выбора форматов (`#feedFormatsDropdownWrap`)**:
   - Заменен одиночный `<select>` на кастомный выпадающий список со справочником `PublicationConfig.FORMATS`.
   - Поведение текста на кнопке-триггере:
     * 0 выбрано: «Все форматы».
     * 1 выбран: точное название формата (например, «Туториал»).
     * 2+ выбрано: «Выбрано форматов: N».
   - Выбранные значения отображаются удаляемыми метками-чипами (`.filter-selected-chip`) под полем.
   - Выбор элемента не закрывает список; доступен поиск по названиям форматов и кнопка «Очистить выбор».
   - Сохранен скрытый `<select id="feedFormatSelect">` для полной обратной совместимости с существующими тестами и формами.

### 1.4. Множественный выбор целевых аудиторий
1. **Компонент множественного выбора аудиторий (`#feedAudiencesDropdownWrap`)**:
   - Заменен одиночный `<select>` на множественный выбор из справочника `PublicationConfig.AUDIENCES`.
   - Поведение текста на триггере: «Все аудитории», либо название, либо «Выбрано аудиторий: N».
   - Удаляемые чипы под полем, локальный поиск по аудиториям, кнопка «Очистить выбор».
   - Сохранен скрытый `<select id="feedAudienceSelect">` для синхронизации.

### 1.5. Логика совместной фильтрации на сервере и клиенте
1. **Правила фильтрации**:
   - Значения внутри одной группы объединяются через логическое **ИЛИ** (выбраны форматы «Туториал» и «Кейс» $\rightarrow$ статьи с любым из них).
   - Различные группы фильтров объединяются через логическое **И** (форматы И аудитории И типы И сложность).
   - Пустой выбор означает отсутствие ограничений (допускаются также статьи с пустым полем формата/аудитории).
2. **Поддержка на сервере (`server.py`)**:
   - `handle_get_articles_list` поддерживает одиночные (`format`, `audience`), множественные параметры (`formats`, `audiences`) в виде списков или значений через запятую.
   - Полная обратная совместимость со старыми URL-ссылками.
3. **Клиентская фильтрация и синхронизация URL (`feed.js`)**:
   - `state.filters.formats` и `state.filters.audiences` (массивы значений).
   - `syncURL()` и `parseURLParams()` корректно сохраняют и восстанавливают массивы в строке адреса браузера.

### 1.6. Единый дизайн выпадающих списков
1. **Унифицированный контроллер (`setupGenericMultiselect`)**:
   - Единый компонент и разметка для тем, форматов и аудиторий.
   - Поверхность в цветах темы (`var(--feed-surface)`), граница `var(--feed-border)`, скругление 8px, шрифт Onest, мягкая тень.
   - Интеллектуальное адаптивное открытие: при недостатке места снизу меню автоматически добавляет класс `.opens-up`, раскрываясь вверх без перекрытия закрепленного футера.
   - Клавиатурное управление: стрелки вверх/вниз, Enter/Space для выбора, фокус в поле поиска.
   - Клавиша Escape: первое нажатие закрывает открытый выпадающий список с возвратом фокуса на триггер; второе нажатие закрывает саму панель фильтров.

### 1.7. Единые чистые метки выбранных значений (чипы)
1. **Стилизация чипов (`.filter-selected-chip`)**:
   - Мягкий фон с тонкой границей (`rgba(56, 189, 248, 0.12)` в темной теме, `rgba(37, 99, 235, 0.08)` в светлой теме).
   - Кнопка удаления (`.filter-selected-chip-remove`) лишена стандартных браузерных серых рамок и фона (`background: transparent !important; border: none !important;`).
   - Аккуратная векторная SVG-иконка крестика с доступным `aria-label`.

### 1.8. Полировка пользовательского интерфейса
1. **Шеврон селектора даты**: в поле «Дата публикации» добавлен векторный шеврон `.feed-select-chevron`, синхронизированный по внешнему виду с остальными селектами.
2. **Сложность «Не указан»**: длинный текст «Без указанного уровня» сокращен до лаконичного «Не указан» с всплывающей подсказкой `title="Автор не указал сложность"`. Все кнопки выбора сложности выровнены по высоте 38px (`height: 38px; min-height: 38px; box-sizing: border-box;`).
3. **Нейтральный индикатор несохраненных изменений**: в панели настроек индикатор заменен на аккуратную круглую серую точку `.feed-unsaved-dot` с надписью «Изменения не сохранены».
4. **Уточненный подзаголовок настроек**: «Выберите, что читать и что скрывать» с разделением зон действия для персональной ленты и общих исключений.

### 1.9. Режимы ленты и визуальные состояния
1. **Динамический заголовок**: в `#feedTitleHeading` отображается актуальный режим («Лента публикаций» для всех статей, «Моя лента» для персональной, «Сохраненные» для закладок).
2. **Тост при сохранении настроек**: при сохранении настроек из режима общей ленты выводится тост «Настройки сохранены» с интерактивной кнопкой действия «Открыть мою ленту» (`showToast(msg, 'Открыть мою ленту', () => switchTab('my'))`).
3. **Индикатор непримененных фильтров**: при изменении параметров фильтрации в панели отображается нейтральный индикатор `#feedFiltersUnappliedIndicator` («Изменения не применены»).
4. **Счетчик групп фильтров**: бейдж на кнопке «Фильтры» считает строго количество активных примененных групп ограничений (без поисковой строки и сортировки).

### 1.10. Черновик и плавный переход к результатам
1. **Сохранение черновика**: объект `filtersDraftState` временно сохраняет выбранные в панели фильтры при закрытии или переключении на панель настроек.
2. **Скролл при применении**: нажатие «Применить фильтры» закрывает панель и плавно скроллит страницу к началу выборки публикаций (`#feedDirectToolbar`).

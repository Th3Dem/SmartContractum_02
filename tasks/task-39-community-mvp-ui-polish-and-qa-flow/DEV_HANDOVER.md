### 1. Выполненные задачи и архитектурные решения

#### 1.1. Меню второго уровня (`#feedSubnavBar`)
- **Проблема**: Кнопка «Создать +» находилась слева, а навигационные табы были прижаты вправо через `space-between`, создавая визуальный провал по центру.
- **Решение**:
  - В [feed.css](file:///home/dem/Projects_02/frontend/public/css/feed.css) контейнер `.feed-subnav-container` переведён на `justify-content: flex-start; gap: 8px;`.
  - После кнопки создания добавлен аккуратный разделительный отступ `.feed-create-dropdown-wrap { margin-right: 8px; flex-shrink: 0; }`.
  - Структура вкладок выстроена последовательно: `Создать + · Все публикации · Вопросы · Подписки · Сохраненные`.
  - Сохранено активное состояние вкладок и числовой бейдж сохранённых материалов.
  - На мобильных экранах (`@media (max-width: 768px)`): контейнер получил горизонтальную прокрутку без переноса строк (`overflow-x: auto; flex-wrap: nowrap; -webkit-overflow-scrolling: touch; scrollbar-width: none;`), что предотвращает горизонтальный скролл страницы.
  - Поиск, сортировка и фильтры сохранены в локальной панели над публикациями (`#feedLocalToolbar`).

#### 1.2. Приветственный баннер сообщества
- **Проблема**: Верхний баннер и правый блок дублировали друг друга и содержали неподтверждённые обещания («ответы проверенных экспертов»).
- **Решение**:
  - В [feed.html](file:///home/dem/Projects_02/frontend/public/feed.html) тексты приведены к утверждённым формулировкам:
    - Заголовок: *«Сообщество российских коммерческих смарт-контрактов»*
    - Описание: *«Задавайте вопросы, делитесь опытом разработки и применения смарт-контрактов, находите коллег»*.
  - Убраны обещания гарантированных экспертов.
  - Состояние закрытия баннера сохраняется в `localStorage` (ключ `sc_welcome_dismissed_v2`) и персистится на сервер для авторизованных пользователей через расширенный эндпоинт `POST /api/user/feed-settings` (`welcomeDismissed: true`).
  - При загрузке ленты [feed.js](file:///home/dem/Projects_02/frontend/public/js/feed.js) проверяет статус и скрывает баннер, если он был закрыт ранее.

#### 1.3. Компактный правый блок действий («Нужна помощь?»)
- **Проблема**: Правый блок «Сообщество экспертов» дублировал баннер и обещал регламентированное время ответа.
- **Решение**:
  - Заголовок: *«Нужна помощь?»*
  - Описание: *«Опишите задачу — обсудим ее вместе»*.
  - Кнопки:
    - Основная: *«Задать вопрос»* -> ведёт в `editor.html?type=question`.
    - Второстепенная: *«Написать публикацию»* -> ведёт в `editor.html`.
  - Удалены неподтверждённые тайминги ожидания.

#### 1.4. Корректное обозначение вопросов и карточки
- **Проблема**: Вопросы в демо-данных ошибочно помечались бейджем `FAQ`, искажая назначение публикаций.
- **Решение**:
  - В [seed_data.py](file:///home/dem/Projects_02/seed_data.py) для вопросов `art-24`, `art-29`, `art-30` формат исправлен с `faq` на `none`.
  - В [card.js](file:///home/dem/Projects_02/frontend/public/js/card.js) реализована отрисовка явного бейджа `<span class="meta-badge question-badge">Вопрос</span>` при `materialType === 'question'`, а отображение формата (включая FAQ) для вопросов подавляется.
  - Кнопка «Ответить» в карточках вопросов без ответа ведёт на `article.html?id=<id>#comment-form`.
  - В [article.js](file:///home/dem/Projects_02/frontend/public/js/article.js) добавлена обработка хэша `#comment-form`: для гостя открывается модальное окно авторизации с сохранением контекста, а для авторизованного пользователя форма ответа плавно фокусируется.
  - Сохранены тема, количество ответов, статус «Без ответов», отметка принятого решения и закладки.

#### 1.5. Оформление имён авторов
- **Проблема**: Вокруг кнопок профиля авторов отображались грубые тёмные рамки.
- **Решение**:
  - В [feed.css](file:///home/dem/Projects_02/frontend/public/css/feed.css) и [theme.css](file:///home/dem/Projects_02/frontend/public/css/theme.css) класс `.btn-author-profile` полностью очищен от рамок, фона и лишних внутренних отступов (`border: none; background: transparent; padding: 0; font: inherit; color: inherit;`).
  - Сохранён доступный фокус с клавиатуры через `:focus-visible` (контур `outline: 2px solid var(--accent-primary, #6366f1)` с `outline-offset: 2px`).

#### 1.6. Блок «Темы»
- **Проблема**: В виджете присутствовали две конфликтующие кнопки перехода: «Показать все (13)» и «Все темы».
- **Решение**:
  - Оставлен единый аккуратный переход: `Все темы · <span id="widgetTopicsTotalCount">N</span>` (количество тем динамически рассчитывается из активного справочника тем).
  - Подпись изменена с «Количество опубликованных статей» на *«Количество публикаций»*.
  - Клик по конкретной теме в сайдбаре фильтрует текущую ленту по выбранной теме с установкой активного чипа.

#### 1.7. Виджет «Вопросы без ответа»
- **Проблема**: Отсутствовал блок для быстрой навигации по открытым вопросам сообщества.
- **Решение**:
  - Добавлен виджет `#widgetUnansweredQuestions` в [feed.html](file:///home/dem/Projects_02/frontend/public/feed.html) сразу после блока «Нужна помощь?».
  - Показывает до 3 опубликованных вопросов с `answersCount === 0`.
  - При отсутствии таких вопросов виджет автоматически скрывается (`display: none`).
  - В футере блока расположена ссылка `Все вопросы без ответа →`, которая переключает ленту на вкладку «Вопросы» с предустановленным фильтром «Без ответов».
  - Очерёдность блоков в правой колонке:
    1. Нужна помощь?
    2. Вопросы без ответа (при наличии)
    3. Темы
    4. О платформе

#### 1.8. Двупользовательский сквозной сценарий и серверный контроль прав
- **Решение**:
  - В [server.py](file:///home/dem/Projects_02/server.py):
    - В `handle_get_article_by_id` добавлены поля `answersCount` и `hasSolution`.
    - В `handle_moderation_submit` поддержано автоматическое связывание с текущим авторизованным пользователем (`curr_user.get("id")`), если `authorId` не передан в теле запроса.
    - В `handle_post_comment_solution` подтверждена серверная защита от несанкционированного принятия решений: только создатель вопроса (`art_author_id == user["id"]`) имеет право отмечать или снимать отметку решения. Чужой пользователь получает `403 Forbidden`.
    - Генерация уведомлений `new_answer` (для автора вопроса) и `solution_accepted` (для автора ответа) с доставкой в `/api/notifications`.

# Task: task-29-feed-cover-fullwidth-and-media-storage — Полноширинная обложка, общий компонент карточки, серверное хранилище медиа и глубокое декодирование изображений

- **Цель**:
  1. **Полноширинная обложка в карточке**:
     - Полная отмена ограничения ширины обложки в 560 px в `PublicationConfig.COVER`, CSS-переменных (`--card-cover-max-width`), стилях ленты (`feed.css`) и предпросмотра (`editor.css`).
     - Обложка занимает 100% внутренней доступной ширины карточки (от левого до правого внутреннего отступа).
     - Сохранение фиксированных пропорций 39:22 (`aspect-ratio: 39 / 22; width: 100%; height: auto;`).
     - Описание расположено строго под изображением.
     - Полная адаптивность на мобильных устройствах без горизонтальной прокрутки.
     - Отсутствие искажений и повторного обрезания.
  2. **Общий компонент формирования карточки (`frontend/public/js/card.js`)**:
     - Единая точка генерации разметки карточки для ленты (`feed.js`) и живого предпросмотра публикации (`publication.js`).
     - Единый 7-ступенчатый порядок: Автор и дата -> Заголовок -> Бейджи -> Обложка -> Описание -> Ключевые слова (#хэштеги) -> Время чтения и действия.
     - Согласованное оформление, отступы, пропорции 39:22 и полноширинное заполнение.
     - Явное разграничение режима предпросмотра (без реальной даты публикации и активных читательских кнопок).
  3. **Серверное хранение медиа и доставка**:
     - Организация постоянного серверного файлового хранилища в `data/media/<sha256>.<ext>`.
     - Автоматическое сохранение base64 обложек в постоянные файлы при приеме на модерацию (`POST /api/moderation/submit`) и через эндпоинт `POST /api/media/upload`.
     - Раздача статических медиа-файлов по URL `/media/<filename>` через HTTP-сервер (`server.py`) с валидацией путей, MIME-типами и кешированием.
     - В публичных ответах API (`GET /api/articles`, `GET /api/articles/<id>`) возвращается публичный URL `/media/...`; исходники и параметры кадрирования в публичную выдачу ленты не попадают.
     - Полная обратная совместимость с существующими черновиками и записями, содержащими Data URL.
  4. **Глубокая серверная проверка и декодирование изображений**:
     - Полноценная проверка целостности и декодируемости файлов на сервере (чистый Python, zero external dependencies).
     - PNG: проверка структуры чанков, CRC32, декомпрессия IDAT через `zlib`, валидация IEND.
     - JPEG: разбор сегментов/маркеров, валидация SOF, извлечение размеров, проверка EXIF-ориентации, требование корректного маркера конца файла EOI `\xff\xd9`, отклонение усеченных данных.
     - GIF: проверка сигнатур `GIF87a`/`GIF89a`, логического дескриптора экрана, дескриптора первого кадра, подтверждение статичности результата.
     - WebP: разбор контейнера RIFF, чанков VP8/VP8L/VP8X, валидация размеров и флагов анимации.
     - Ограничение максимального разрешения в пикселях (`MAX_IMAGE_PIXELS = 25_000_000`) для предотвращения атак декомпрессии.
     - Проверка соответствия пропорциям 39:22 (с допуском epsilon) для подготовленной обложки.
     - Проверка существования файла при передаче путей вида `/media/...`.
     - Информативные ошибки валидации с сохранением ранее загруженной обложки.
  5. **Чистота обложки (Zero Site Overlays)**:
     - Обложка отображает исключительно загруженное автором изображение без наложения со стороны сайта заголовков, логотипов, водяных знаков, плашек, затемнений или рамок.
  6. **Обработка состояний загрузки и ошибок**:
     - Без обложки: 0px пустоты.
     - Загрузка: резервирование места по 39:22 с шиммер-анимацией.
     - Загружено: полный выбранный кадр на 100% ширины.
     - Ошибка загрузки: автоматический переход в чистый текстовый вид (0px пустоты, без сломанных иконок).
     - Отмена замены не стирает существующую обложку.
  7. **Тестовое покрытие**: 100% прохождение всех unit- и интеграционных тестов проекта.
